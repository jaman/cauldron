# CauldronSFX

A sound-effect editor in a terminal: a game's events, what each one sounds like, and the
keys to change it while you hear it. It edits a [`Cauldron.SFX`](https://hexdocs.pm/cauldron_core/Cauldron.SFX.html) bank,
which the game loads at run time.

```console
$ mix cauldron.sfx priv/sfx/sfx.json
```

With no file it opens the starter bank, so a first run can create one:

```console
$ mix cauldron.sfx --out priv/sfx/sfx.json
```

Then `w`, and the game reads it:

```elixir
bank = Cauldron.SFX.read!("priv/sfx/sfx.json")
Cauldron.Audio.start(sounds: Cauldron.SFX.sounds(bank))
```

## Keys

| Key | What it does |
| --- | --- |
| ↑ ↓ | the event |
| ← → | the variant |
| `p` | play the event |
| `s` | the tone's shape: sine, square, saw, triangle |
| `+` `-` | the event's gain |
| `>` `<` | the event's pan |
| `]` `[` | the variant's pitch, a semitone |
| `1` `2` | the variant's decay, shorter and longer |
| `3` `4` | the tone's sweep, less and more |
| `5` `6` | the variant's cutoff, darker and brighter |
| `7` `8` | the variant's attack, shorter and longer |
| `9` `0` | the variant's release, shorter and longer |
| `k` `l` | the event's space, less and more |
| `t` | which preset a new event starts from |
| `a` | add a variant, a copy of this one |
| `d` | remove this variant |
| `n` | name a new event, `enter` to add it, `escape` to drop it |
| `x` | remove the event |
| `w` | write the bank |
| `q` | quit |

The names are the events your game plays: `Cauldron.Audio.play([:laser])` needs an event
called `laser`. A compound event such as `{:bomb, by}` stays in the game's own `sounds/0`.

## What it is, and is not

It edits **recipes**: a tone's shape, pitch, decay, sweep, cutoff and pan; a noise's decay
and filter; a layer's parts and their offsets. Not waveforms. A layered variant and a noise
are shown but not edited note by note.

The bank is JSON, so the same file can be edited by hand, generated by a tool, or read by a
game with `cauldron_core` alone. An event may have several variants, and one is picked each
time it plays, so a repeated event does not sound repeated.

## Front ends

The editor itself is `Cauldron.SFX.Editor` in `cauldron_core`: the state, the keys, the
commands a button would send, and `view/1` — a plain map of rows, detail, message and help
keys. It draws nothing and plays nothing; anything to be *done* comes back as an effect,
`{:play, sound}` or `:quit`.

This package is the terminal front end, `Cauldron.SFX.Editor.Drafter`. A web (LiveView),
notebook (Livebook) or native front end draws the same `view/1`, sends the same keys or
commands, and decides for itself what a `{:play, sound}` sounds like. The atlas editor is
the worked example of that split: `cauldron_2d_easel` holds the model, and
`cauldron_2d_easel_drafter`, `_web` and `_kino` each hold a front end.

## Where the sound comes from

`Cauldron.Audio.Voice` — the same voices a game already plays. That means an effect made
here is a `Cauldron.Audio` sound like any other, and a game can play it without knowing the
bank exists.
