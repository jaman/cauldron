# Editing sounds

A game's sound effects are recipes, not recordings: a tone's shape and pitch, a noise,
layers of them, or a sample. They live in one JSON bank, which a game loads at run time.
`cauldron_sfx` is the terminal editor for that bank. The bank itself and the voices it
makes are `Cauldron.SFX`, in `cauldron_core`; this package adds the editor front end and
the import task.

## A bank is data

`sfx.json` is plain JSON. It can be read, diffed, edited by hand or generated by a tool
without this library.

```json
{
  "format": 1,
  "rate": 44100,
  "channels": 2,
  "events": {
    "fire": {
      "gain": 1.0,
      "pan": 0.0,
      "space": 0.0,
      "priority": 1,
      "variants": [
        {
          "kind": "tone",
          "shape": "square",
          "freq": 1320.0,
          "decay": 0.05,
          "sweep": 0.6,
          "gain": 0.8,
          "cutoff": 0.6,
          "pan": 0.0
        }
      ]
    }
  }
}
```

| Field | What it is |
| --- | --- |
| `format` | The bank's version, `1` |
| `rate`, `channels` | What a bake would render at; playback uses the stage's own |
| `events` | A map from event name to event |
| `gain`, `pan` | The event's own level and place, over every variant |
| `space` | How much cheap room it gets: three early reflections, quieter and across |
| `variants` | The recipes one of which is picked each time the event plays |

A variant is one recipe. `"kind": "tone"` has a `shape` (`sine`, `square`, `saw` or
`triangle`), a `freq`, a `decay` in seconds, a `sweep` as a multiple of the frequency, and
optional `attack`, `sustain`, `hold`, `release`, `cutoff`, `highpass`, `fm`, `fmh`,
`fmattack`, `detune` and `pan`. `"kind": "noise"` has no pitch: its `decay` and filters
shape it. `"kind": "layers"` holds `parts`, each a `recipe` played `at_ms` after the
event. `"kind": "sample"` plays a recording: `sound` names one of `TuningFork.Kit`'s, or
`file` is a path.

Several variants make a repeated event sound less repeated: one is picked each time.
A layered variant and a sample can be shown in the editor but not edited note by note.

## Opening the editor

```console
$ mix cauldron.sfx priv/sfx/sfx.json
$ mix cauldron.sfx --starter --out priv/sfx/sfx.json
$ mix cauldron.sfx --out priv/sfx/sfx.json
```

With a file, the editor opens that bank. Without one, or with `--starter`, it opens
`Cauldron.SFX.starter/0`, so a first run can create a bank: press `w` to write it.

| Option | What it does |
| --- | --- |
| `--out PATH` | Where `w` writes. Default the file given, or `sfx.json` |
| `--starter` | Open the starter bank even when a file is given |

`mix cauldron.sfx` starts the application before it opens the editor. It writes only when
asked; quitting without `w` leaves the file as it was.

## The keys

| Key | What it does |
| --- | --- |
| ↑ ↓ | The event |
| ← → | The event's variant |
| `p` | Play the event |
| `s` | The tone's shape: sine, square, saw, triangle |
| `+` `-` | The event's gain |
| `>` `<` | The event's pan |
| `]` `[` | The variant's pitch, a semitone |
| `1` `2` | The variant's decay, shorter and longer |
| `3` `4` | The tone's sweep, less and more |
| `5` `6` | The variant's cutoff, darker and brighter |
| `7` `8` | The variant's attack, shorter and longer |
| `9` `0` | The variant's release, shorter and longer |
| `k` `l` | The event's space, less and more |
| `t` | Which preset a new event starts from |
| `a` | Add a variant, a copy of this one |
| `d` | Remove this variant |
| `n` | Name a new event: `enter` adds it, `escape` drops it |
| `x` | Remove the event |
| `w` | Write the bank |
| `q` | Quit |

A name is typed in the editor after `n`: lowercase letters, digits and underscores, with
`backspace` to correct it. The names are the events the game plays:
`Cauldron.Audio.play([:laser])` needs an event called `laser`. A compound event such as
`{:bomb, by}` stays in the game's own `sounds/0`, not in the bank.

The keys change the recipe the selected variant holds. `s` says so when the variant is a
noise or layers; pitch and sweep only exist for a tone; decay, cutoff, attack and release
only for a tone or a noise. An event keeps at least one variant.

## The starter bank

`Cauldron.SFX.starter/0` is a bank to start from: `fire`, `boom`, `pickup`, `hurt`, `jump`
and `click`. Each has a few variants; `boom` and `hurt` are layered, so an editor opened
on it has something to play with.

`t` cycles the presets a new event starts from
(`Cauldron.SFX.Presets.names/0`): laser, zap, coin, jump, explosion and the rest. A preset
is a whole event recipe, not a bare tone, so a new event lands on something finished.

## Importing recordings

`mix cauldron.sfx.import` turns a WAV into an event's variants. It cuts the recording at
silence, or into equal parts, normalises each cut, writes the cuts beside the bank and
lists them as sample variants of one event.

```console
$ mix cauldron.sfx.import woodpecker.wav --bank priv/sfx/sfx.json
$ mix cauldron.sfx.import thunder.wav --bank priv/sfx/thunder --event boom --slices 3
```

| Option | What it does |
| --- | --- |
| `--bank PATH` | The bank, a directory or a `sfx.json` file. Default `priv/sfx/sfx.json` |
| `--event NAME` | The event the variants go on. Default the WAV's file name |
| `--slices N` | Cut into `N` equal parts instead of at silence |
| `--silence-db DB` | What counts as silence. Default `-50` |
| `--gap-ms MS` | How long a silence cuts. Default `120` |
| `--pad-ms MS` | How much silence either side of a cut to keep. Default `10` |
| `--peak-db DB` | The level each cut is normalised to. Default `-1` |
| `--gain GAIN` | The variants' gain in the bank. Default `0.8` |

The cuts are written as `<event>-<n>.wav` in the bank's directory and listed with a
relative `file`, so the bank directory can move. The bank is created when it does not
exist, and existing events are kept. Only 16-bit PCM WAVs are read and written, and only
mono and stereo.

From code, `Cauldron.SFX.Import.add/3` does the same and answers the bank:

```elixir
{:ok, bank} =
  Cauldron.SFX.Import.add("woodpecker.wav", "priv/sfx/sfx.json", event: "woodpecker")
```

## Loading what the editor wrote

The game reads the bank and hands its sounds to `Cauldron.Audio`:

```elixir
bank = Cauldron.SFX.read!("priv/sfx/sfx.json")
Cauldron.Audio.start(sounds: Cauldron.SFX.sounds(bank))
Cauldron.Audio.play([:fire])
```

`Cauldron.SFX.read!/1` reads a file or a directory holding `sfx.json`, and resolves a
sample's relative `file` against the bank's directory. `Cauldron.SFX.sounds/1` is the
function `Cauldron.Audio.start/1` takes as `:sounds`: it turns an event name into the
voice to play. Play the events the game emits; the audio stage picks a variant.

To hear one variant while writing code, `Cauldron.SFX.voice/3` takes the bank, the event
and options, `:variant` naming which one:

```elixir
Cauldron.SFX.voice(bank, "fire", variant: 1)
```

`Cauldron.SFX.read/1` answers `{:ok, bank}` or `{:error, reason}`;
`Cauldron.SFX.manifest/1` says where a bank's `sfx.json` is.

## The editor and other front ends

The state, the keys and the view are `Cauldron.SFX.Editor`, in `cauldron_core`. This
package's `Cauldron.SFX.Editor.Drafter` draws that view in a terminal and turns
`{:play, sound}` into a stage call. Another front end draws the same `view/1` and sends
the same keys or commands.

```elixir
state = Cauldron.SFX.Editor.mount(%{bank: Cauldron.SFX.starter()})
{state, effects} = Cauldron.SFX.Editor.key(state, :p)
Cauldron.SFX.Editor.view(state)
```

`mount/1` takes `:bank` and `:out`. `key/2` reads a key as `command/2` does and then does
it. `command/2` takes the command directly, such as `{:new_event, "laser"}` or `:write`.
Anything to do comes back as an effect, `{:play, sound}` or `:quit`; the editor touches no
device.
